## Phase 0 — Setup (week 0, about 3 days)
- [x] Install Rust (minimal profile, GNU toolchain; see PROJECT_PLAN §6) and VS Code + rust-analyzer
- [x] `git init`, `.gitignore`, create GitHub repo
- [x] Cargo workspace skeleton with empty crates (`sim-api`, `sim-core`, `sim-net`, `sim-disk`, `checker`, `raft`, `kv`, `dst-cli`)
- [x] `clippy.toml` determinism lint (F22); `rustfmt.toml`
- [x] Workspace profile: `debug = "line-tables-only"` to save disk
- [x] Minimal CI: build + test + clippy on push

**Done when:** `cargo test` and `cargo clippy` pass on an empty workspace, locally and in CI.

## Phase 1 — Simulation core (weeks 1–2) → M1
- [x] Seeded RNG with forked per-subsystem streams (F1)
- [x] Virtual clock + event queue ordered by `(time, seq)` (F2)
- [x] `Node` trait and `Context` API (F3)
- [x] Simulator main loop: deliver messages, fire timers, stop at time / step limit
- [x] Trace recorder + running trace hash (F11)
- [x] Toy protocol: ping-pong and a gossip broadcast
- [x] Determinism test: 100 seeds × 2 runs, hashes equal

**Done when:** `cargo test` proves the same seed gives an identical trace and different seeds diverge.

## Phase 2 — Fault-injecting network and nodes (week 3) → M2
- [x] Latency distribution, drop, duplicate, reorder (F4)
- [x] Partitions: symmetric, asymmetric, isolate-one, heal (F4)
- [x] Node crash and restart, wiping volatile state (F5)
- [x] Per-node clock drift and offset (F6)
- [x] Gossip toy protocol eventually converges after partitions heal

**Done when:** unit tests verify each fault; gossip test passes across 1,000 seeds.

## Phase 3 — Simulated disk (week 4) → M3
- [x] `Storage` trait: write / read / fsync / size (F7)
- [x] Volatile vs durable layers; crash discards unsynced data
- [x] Faults: torn writes, fsync error (latency spikes dropped: synchronous API)
- [x] Record format with CRC32 checksums (prepares for F18)

**Done when:** tests show "write, no fsync, crash" loses data and "write, fsync, crash" keeps it; torn writes are detected by the checksum.

## Phase 4 — Raft KV store (weeks 5–7) → M4
- [x] Week 5: leader election (randomised timeouts, `RequestVote`, terms); persistent term and vote
- [x] Week 6: log replication (`AppendEntries`, conflict truncation, commit index, apply)
- [x] Week 7: KV state machine (`get`/`put`/`cas`), clients with retries and request IDs (F8)
- [x] Safety invariants checked every step (F9)
- [x] Crash recovery from the simulated disk

**Done when:** 10,000 seeds with all Phase 2–3 faults enabled show no invariant violations.

## Phase 5 — Linearizability checker (week 8) → M5 = MVP ✅
- [ ] History types: invoke / ok / fail / info (timeout = unknown outcome) (F10)
- [ ] WGL search with memoisation; per-key partitioning
- [ ] Unit tests: handcrafted good and bad histories (including Porcupine's examples)
- [ ] Integrate: every simulation run's history gets checked
- [ ] First README draft + architecture diagram

**Done when:** a deliberately broken KV (for example, reads served by followers) is flagged non-linearizable within 1,000 seeds, and the correct one passes 10,000.

> **MVP gate:** nothing from Phase 6 starts until M5 is met and committed.

## Phase 6 — Bug hunter (weeks 9–10) → M6
- [ ] `dst` CLI: `run`, `replay`, `sweep --jobs N` with `rayon` (F12)
- [ ] Planted-bug suite (6 bugs) behind a `--bug <name>` flag; seeds-to-detect report (F13)
- [ ] Swarm testing: per-seed random fault mix (F14)
- [ ] `buggify!()` macro and about 5 BUGGIFY points in Raft and KV (F15)
- [ ] CI: sweep 10,000 seeds per push; upload failing seeds (F23)

**Done when:** every planted bug is caught and the table of seeds-to-detect is generated by a command.

## Phase 7 — Advanced features (weeks 11–13) → M7
- [ ] Week 11: failure shrinking via delta debugging (F16) + disk corruption and checksum recovery (F18)
- [ ] Week 12: HTML trace viewer (F17) + ReadIndex reads (F20)
- [ ] Week 13: snapshots and log compaction (F19) + real-mode runtime with a kill-and-recover demo (F21)

**Done when:** `dst shrink --seed X` outputs a minimal trace that opens in the viewer; real-mode demo is recorded as a GIF.

## Phase 8 — Polish and ship (weeks 14–15) → M8
- [ ] Measure and fill in all metrics (PROJECT_PLAN §5); flamegraph
- [ ] README: pitch, diagram, viewer screenshot, metrics table, quick start, "how determinism works"
- [ ] `docs/BUG_MUSEUM.md`: every real bug found in my own Raft, with seed, trace and fix
- [ ] Nightly CI sweep; Linux + Windows matrix
- [ ] Optional blog post; resume bullets with real numbers; interview talking points
- [ ] Code cleanup, doc comments, `cargo doc`

## Week 16 — Buffer
Slack for exams, placements and Raft debugging. If unused, start Tier 3 (F24–F28).
